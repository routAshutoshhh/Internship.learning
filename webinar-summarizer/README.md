# 🎙️ Webinar Insight Studio

Automated **Document Summarization & Interactive QA System** for long
webinar transcripts — built with **LangChain**, **FAISS**, and a local
**Ollama** LLM, wrapped in a polished **Streamlit** UI.

Upload a 3–4 hour webinar transcript PDF and instantly get:
- A concise, marketing-focused summary (Overview / Frameworks / Actionable Takeaways)
- A searchable FAISS vector index of every chunk + the summary itself
- A chat interface to ask free-form questions grounded in your transcripts

Everything runs **locally** — no data leaves your machine.

---

## 1. Prerequisites

- Python 3.10+
- [Ollama](https://ollama.com/) installed and running locally
- At least one chat model pulled, e.g.:

```bash
ollama pull llama3
ollama serve   # if not already running as a background service
```

> Embeddings default to a local HuggingFace model (`all-MiniLM-L6-v2`), so
> you do **not** need to pull an Ollama embedding model unless you set
> `EMBEDDING_PROVIDER=ollama` in `config.py`.

## 2. Setup

```bash
cd webinar-summarizer
python -m venv .venv
source .venv/bin/activate        # Windows: .venv\Scripts\activate
pip install -r requirements.txt
```

## 3. Run the app

```bash
streamlit run app.py
```

Then open the local URL Streamlit prints (usually `http://localhost:8501`).

## 4. Using it

1. **Sidebar → Ingest a Webinar**: upload a transcript PDF, pick a
   summarization strategy (`map_reduce` for very long transcripts,
   `refine` for a more narrative pass), and click **Process Transcript**.
2. Watch the live status log: save → load & chunk → index into FAISS →
   summarize → persist summary + metadata.
3. The **Latest Summary** panel shows the generated summary; **All
   Summaries** lets you revisit past webinars; the **FAISS Vector Store
   Inspector** lets you browse indexed chunks/metadata per webinar.
4. Scroll down to **Ask Questions About Your Webinars** and chat — answers
   are retrieved from FAISS and generated by your local Ollama model, with
   sources shown under each response.

```
webinar-summarizer/
├── README.md
├── requirements.txt
├── app.py                  # Streamlit UI entry point
├── config.py               # Models, chunk sizes, paths
├── data/                   # Created at runtime: uploads, FAISS index, summaries.json
└── src/
    ├── __init__.py
    ├── loader.py           # PyPDFLoader + RecursiveCharacterTextSplitter
    ├── vector_store.py     # FAISS create/load/save, metadata inspector
    ├── summarizer.py       # map_reduce / refine summarization chains
    └── qa_engine.py        # LCEL retrieval-augmented QA chain
```

## 6. Configuration

All tunables live in `config.py` (or as environment variables of the same
name): `OLLAMA_CHAT_MODEL`, `OLLAMA_BASE_URL`, `EMBEDDING_PROVIDER`,
`HF_EMBEDDING_MODEL`, `OLLAMA_EMBEDDING_MODEL`, `CHUNK_SIZE`,
`CHUNK_OVERLAP`, `SUMMARY_CHAIN_TYPE`, `RETRIEVER_TOP_K`.

## 7. Notes on scaling to 50+ page transcripts

- `PyPDFLoader` loads page-by-page rather than the whole file as one blob,
  keeping memory low.
- The `map_reduce` summarization chain summarizes chunks independently
  first, then combines those partial summaries — so it scales to
  arbitrarily long transcripts without hitting context-window limits.
- FAISS indexing and retrieval scale to many thousands of chunks with fast
  approximate similarity search.

## 8. Troubleshooting

- **"Couldn't reach the local LLM"** → confirm `ollama serve` is running
  and `ollama list` shows the model set in `OLLAMA_CHAT_MODEL`.
- **Slow summarization on first run** → the HuggingFace embedding model is
  downloaded once and cached locally afterward.
- **Re-processing the same file** → summaries are keyed by a hash of the
  filename, so re-uploading the same file replaces its previous summary
  record.
